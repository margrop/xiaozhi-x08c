# 唤醒词与连续对话（已实现）

客户端使用本地 Sherpa-ONNX KWS，不需要云端唤醒服务。

## 关键词路由

| 关键词 | 路由 |
| --- | --- |
| 小智小智 | 小智 auto 会话 |
| 小屁小屁 | 小智 auto 会话 |
| 小爱同学 | 不接管，交给原厂小爱 |

模型、词表和原生库随 APK 打包在 `app/src/main/assets/kws/` 和 `app/src/main/jniLibs/`。
唤醒开关默认开启，可在应用工具栏关闭。`VoiceAssistantService` 由前台服务承载，
`BootReceiver` 在开机后尝试启动；开机前必须已经授予麦克风权限。

## 一次小智对话

1. 说“小智小智”或“小屁小屁”，或点击“点击说话”；
2. 小智界面立即出现，播放本地随机应答语“我在”“干嘛呀”或“诶”（每段小于 1 秒）；
3. 应答音播放期间暂停上行和 KWS，避免音箱听到自己的声音；
4. 应答结束后进入 `listen mode=auto`，显示“我在听，请讲…”；
5. 用户 10 秒内开始说话，服务端 VAD 在停顿后结束本轮；
6. TTS 播放结束后开启约 5 秒免唤醒跟听，用户可以直接继续说下一句；
7. 跟听窗口无新语音则回到待机时钟。

TTS 播放中再次说任一小智关键词，会立即停止本地播放并发送 `abort`，然后等待新问题。

## 停止命令

只有服务处于小智聆听状态且识别文本完整等于以下之一时才退出：

```text
关闭 / 停止 / 结束 / 退出 / 不用了 / 算了
```

“关闭灯”“停止音乐”等更长指令不会触发退出，会交给正常对话或 Home Assistant 处理。

## 与原厂小爱共存

“小爱同学”不会被本应用接管，原厂服务继续工作。两条语音链路同时运行时可能发生
麦克风抢占、回声或音频焦点问题；应用会检测全零录音并提示，但无法改变原厂服务行为。

## 已知运行约束

- 首次授权麦克风后，如服务早于授权启动，可能需要重开应用；
- 自动唤醒需要前台服务持续运行，会有额外功耗；
- 本地离线 ASR 在服务端 VAD 断句后返回完整 `stt`，不会边说边逐字显示；
- KWS 是固定模型和词表，修改关键词需要重新打包并在目标设备实测。
